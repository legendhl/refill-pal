# 补货小管家 · 部署手册

照着做一遍大约 30 分钟。每一步都写了「怎么判断成功了」，不用猜。

先确认你要准备的东西：

| 需要 | 说明 |
| --- | --- |
| 微信开发者工具 | 已安装并能正常登录（[下载](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)） |
| 一个小程序 AppID | 在 [微信公众平台](https://mp.weixin.qq.com) 注册「小程序」账号后，在「开发 → 开发管理 → 开发设置」里能看到。个人主体也能注册 |
| 一个微信号 | 用于登录开发者工具 |
| 家人的微信号 | 第 7 步要用，家人需要被加为「体验成员」才能扫码打开 |

> 现在就想先看看长什么样？不用做任何配置：`miniprogram/config.js` 里 `USE_MOCK` 默认是 `true`，
> 直接用开发者工具打开本项目就是**演示模式**，带一份示例数据，所有界面都能点。
> 等你把云开发配好了，再把它改成 `false`。

---

## 第 1 步：把项目导入开发者工具

1. 打开微信开发者工具 → 「小程序」→ 「导入项目」
2. 目录选到本项目根目录（有 `project.config.json` 的那一层）
3. AppID 填你自己的 AppID（**不要用测试号**，测试号开不了云开发）
4. 后端服务选「不使用云服务」——我们用的是云开发，但这里选哪个都能在下一步开通

**成功标志**：工具左侧能看到 9 个页面，模拟器里出现「补货小管家」的待补货首页（演示数据）。

如果模拟器里是白屏，先看工具右下角的 Console 有没有红色报错。

---

## 第 2 步：开通云开发，拿到环境 ID

1. 点工具顶部工具栏的「**云开发**」按钮
2. 按提示开通（选按量付费即可，家用远远用不到收费额度；不放心可以先看[免费额度说明](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/billing/price.html)）
3. 环境名称随便起，比如 `refillpal`
4. 开通后进入「云开发控制台 → 设置 → 环境」，复制那一串**环境 ID**（形如 `refillpal-1a2b3c4d5e6f7g8h`）

然后打开 `miniprogram/config.js`，把环境 ID 填进去：

```js
ENV_ID: 'refillpal-1a2b3c4d5e6f7g8h',   // ← 换成你复制的那一串
```

**成功标志**：`config.js` 里的 `ENV_ID` 不再包含 `YOUR-CLOUD-ENV-ID`。

---

## 第 3 步：建 5 个集合

云开发控制台 → 「数据库」→ 左上角「+」新建集合。**逐个建下面这 5 个**（名字必须一模一样，区分大小写）：

| 集合名 | 存什么 |
| --- | --- |
| `families` | 家庭（名称、邀请码、提醒设置） |
| `members` | 家庭成员（openid、昵称、订阅额度） |
| `items` | 物品（名称、分类、单位、初始库存） |
| `events` | 所有流水（购买 / 盘点 / 用完）——这是核心，库存由它算出来 |
| `pushLogs` | 推送日志（幂等与排查用） |

> 漏建集合的话，第一次调用云函数会报 `collection not exists`。

### 每个集合的权限都改成「仅管理端可读写」

选中共集合 → 「权限设置」→ 选「**仅管理端可读写**」→ 保存。5 个都要改。

这是本项目的安全底线：小程序端**不直连数据库**，所有读写都经过云函数，
而云函数里的家庭 ID 是由你的 openid 反查出来的 —— 所以别人即使伪造请求也读不到你家的数据。

### 建索引

选中共集合 → 「索引管理」→「新建索引」。按下面这张表建（**顺序不能反**）：

| 集合 | 索引字段（按顺序） | 唯一 |
| --- | --- | --- |
| `families` | `inviteCode` (升序) | ✅ 是 |
| `members` | `openid` (升序) | ✅ 是 |
| `members` | `familyId` (升序) | 否 |
| `items` | `familyId` (升序) + `status` (升序) | 否 |
| `events` | `familyId` (升序) + `occurredAt` (降序) | 否 |
| `events` | `familyId` (升序) + `itemId` (升序) + `occurredAt` (降序) | 否 |
| `pushLogs` | `familyId` (升序) + `date` (升序) | ✅ 是 |

**`pushLogs` 的唯一索引必须建**：它保证同一天只推一条提醒，是这个功能的幂等保险。

**成功标志**：数据库里能看到 5 个集合，每个集合的索引列表和上表一致。

---

## 第 4 步：上传 6 个云函数

在开发者工具左侧的资源管理器里，找到 `cloudfunctions` 目录：

1. 先确认 `cloudfunctions/` 下每个云函数目录里都有 `shared/core.js` 和 `shared/kit.js`。
   如果没有，在项目根目录执行一次：

   ```bash
   npm run sync
   ```

2. 对 **每一个**云函数目录（`family`、`item`、`purchase`、`dashboard`、`stats`、`notify`）：
   右键 → 「**上传并部署：云端安装依赖（不上传 node_modules）**」

   选这一项是为了让云端自己装 `wx-server-sdk`，省得你本地 `npm install`。

3. `notify` 额外要确认两件事：
   - 右键 `notify` → 「**上传触发器**」（定时触发器不会随代码自动上传）
   - 上传后到「云开发控制台 → 云函数 → notify → 触发器」，应该能看到一条 `hourlyRefillCheck`，cron 是 `0 0 * * * * *`（每小时整点）

**成功标志**：云开发控制台的「云函数」列表里有 6 个函数，`notify` 有 1 条定时触发器。

**关于定时器为什么要每小时跑**：你在小程序里可以把提醒时间设成 6:00 到 23:00 之间的任意整点。
定时器每小时醒一次，只给「当前小时 == 你设的时间」的家庭推送。这样「每天几点推」才是真生效的，
而不是只存不用。想改成固定早上 9 点，把 `cloudfunctions/notify/config.json` 的 cron 改成 `0 0 9 * * * *` 再上传触发器即可。

## 第 5 步：申请订阅消息模板

这一步是整个部署里唯一需要等微信审核的地方（一般几分钟到几小时）。

### 5.1 先确认有可用的服务类目

微信公众平台 → 「设置 → 基本设置 → 服务类目」。如果没有类目或类目偏门，订阅消息模板库会是空的。
工具类小程序一般加「工具 → 效率」或「生活服务 → 家政、维修」即可。

### 5.2 申请模板

公众平台 → 「功能 → 订阅消息」→ 「**公共模板库**」→ 搜「补货」「待办」「提醒」等关键词，
选一个满足这两个条件的模板：

- 至少有 **2 个 thing 类型**字段（文本，单条上限 20 个字符）
- 至少有 **1 个 number 或 time 类型**字段

推荐挑一个像「待办提醒」这样的模板，字段含义大致是：

| 模板里的字段 | 我们的用法 | 代码里的键名 |
| --- | --- | --- |
| 第一个 thing 字段 | 物品汇总，如「抽纸、洗手液」 | `thing1` |
| 第二个 thing 字段 | 最紧急的一条，如「抽纸已经用完了」 | `thing2` |
| number 字段 | 待补货数量 | `number3` |
| time 字段 | 推送时间 | `time4` |

### 5.3 把字段名对上

微信模板库的字段名是固定的（`thing1`、`thing2`、`number3`…），不一定和上表一致。
请打开 `cloudfunctions/_shared/core.js`，找到 `buildPushPayload` 函数，
把里面的键名改成**你申请到的模板实际字段名**，然后：

```bash
npm run sync                 # 把改动同步到 6 个云函数
```

再重新上传 `notify` 云函数（其他函数没用到这个函数，但一起上传也无妨）。

### 5.4 填模板 ID

打开 `miniprogram/config.js`：

```js
SUBSCRIBE_TEMPLATE_ID: '你申请到的模板ID',
```

> 为什么这个 ID 要填在小程序里而不是云函数里？因为云函数发消息时用的模板 ID，
> 是你在小程序里点「续订提醒次数」时顺手存进家庭设置的。填一处就够了，不会出现两处不一致。

**成功标志**：第 6 步之后，在「我的 → 提醒设置 → 预览提醒内容」里能看到 `模板 ID 已记录`。

---

## 第 6 步：关掉演示模式

打开 `miniprogram/config.js`：

```js
USE_MOCK: false,
```

点工具上的「编译」。此时 App 会真的去调云函数。

**成功标志**：首页显示「先建一个『家』」的引导页（因为新环境里还没有数据）。
点进去创建家庭，然后到「物品」页加一个物品，比如：

- 名称：抽纸
- 分类：纸品
- 单位：包
- 现在家里还剩多少：2
- 大概能用多久：15

保存后回到首页，应该能看到「还剩 2 包 / 预计 15 天后用完」。
再去首页点「记一笔」，点一下抽纸，应该看到库存变成 3，底部出现「已记：抽纸 ×1 / 补金额 / 撤销」。

**这一步的成功是整个部署真正成功的标志**——说明小程序、云函数、数据库三者已经打通。

---

## 第 7 步：让家人加入

1. 小程序里：「我的 → 家庭与成员」，看到 6 位邀请码（如 `3XKRM5`）
2. 点「分享给家人」，把卡片发到家庭群
3. 家人点开卡片 → 进入「加入家庭」页 → 自动填好邀请码 → 填个昵称 → 加入

**家人看不到内容？** 大概率是他们用的微信号还不是这个项目的体验成员：

- 公众平台 → 「成员管理 → 体验成员」→ 添加家人的微信号
- 家人重新扫开发者工具里的预览二维码（不是分享卡片）
- 想彻底摆脱这个限制，就需要提交审核并发布

**成功标志**：家人手机上能看到同一份物品列表，家人记的一笔在你这边也能看到。

---

## 第 8 步：让提醒真的能收到

订阅消息有个必须先理解的规则：**用户每授权一次，小程序才能推一条**。
这是微信的限制，不是本项目偷懒。所以设计上做了三件事：

1. **一天只推一条汇总**（正好对上「一次授权 = 一条」）
2. 每次打开小程序，若剩余次数少于 3，首页会出现一张黄色卡片提醒你续订
3. 「我的 → 提醒设置」里也能随时续订

要收到提醒，请确认：

- [ ] 小程序里点过一次「续订提醒次数」，余额 > 0
- [ ] 「提醒设置」里的开关是开的
- [ ] 推送时间是当前小时之后（定时器每小时整点跑）
- [ ] 今天确实有待补货的东西（没有就不推，这是设计如此）
- [ ] 「预览提醒内容」能显示内容

到点之后，去「云开发控制台 → 云函数 → notify → 日志」看执行记录。日志里每个家庭都会有一行原因：

| 日志里的 reason | 含义 |
| --- | --- |
| `SENT` | 推成功了 |
| `NOT_YET` | 还没到你家设定的时间 |
| `ALREADY_PUSHED` | 今天已经推过了（幂等生效） |
| `NOTHING_TO_BUY` | 没有要买的，刻意保持安静 |
| `NO_QUOTA` | 订阅额度用完了，去小程序里续订 |
| `NO_TEMPLATE` | 还没记录模板 ID，去「续订提醒次数」点一次 |
| `DISABLED` | 关掉了提醒 |
| `BAD_PUSH_TIME` | 推送时间格式不对 |
| `ERROR` | 出错了，看日志里的 error 字段 |

如果 `pushLogs` 里有 `kind: TEMPLATE_ERROR`，说明模板字段和代码对不上，回到第 5.3 步。

部署完成后，请按这张表逐条走一遍。**每条都写了预期结果**，不符合就是有问题。

| # | 操作 | 预期 |
| --- | --- | --- |
| 1 | 新建物品：抽纸，还剩 2，能用 15 天 | 物品页出现抽纸，显示「还剩 2 包」「预计 15 天后用完」，可信度「估算中」 |
| 2 | 首页点「记一笔」→ 点抽纸 | 顶部出现「已记：抽纸 ×1」，库存变 3，清单里抽纸还在 |

| 4 | 再记一笔，点「补金额」填 39.9 | 提示「已记上金额」；统计页本月金额包含这笔 |
| 5 | 物品详情 →「用完了」 | 库存变 0，徽标变「已用完」，首页置顶显示 |
| 6 | 物品详情 →「盘点」，填 3 | 库存变 3，提示「已校准」 |
| 7 | 盘点时故意填一个超过历史总量的数 | 弹出二次确认，点「取消」后库存不变 |
| 8 | 物品详情长按一条历史记录 → 改数量 | 库存跟着重算（事件溯源的特性） |
| 9 | 家人加入后，双方各记一笔 | 两边都能看到对方记的那笔 |
| 10 | 用另一个微信号（未加入家庭）尝试访问 | 看不到任何数据（归属校验生效） |
| 11 | 断网后打开首页 | 显示上次缓存的数据，顶部有「离线数据」提示条 |
| 12 | 到推送时间后检查手机 | 收到一条汇总消息；`pushLogs` 里当天只有一条 |

## 常见问题

**「云函数 XXX 还没部署」**
云函数没上传，或者名字拼错了。第 4 步重做一遍。

**「collection not exists」**
集合没建全。第 3 步的 5 个集合都要建。

**首页一直转圈**
看云开发控制台 → 云函数 → 日志。最常见的是 `notify`/`dashboard` 里报数据库权限错误，
说明集合权限没设成「仅管理端可读写」。

**改了代码但行为没变**
两件事都要做：小程序代码改动 → 点工具上的「编译」；云函数代码改动 → 右键重新上传。
另外 `cloudfunctions/*/shared/` 里的文件是 `npm run sync` 自动复制的，
改了 `_shared/` 里的文件一定要跑一次 sync 再上传。

**数据算得不准**
去物品详情点一次「盘点」，把实际剩余量填进去。盘点是最有价值的输入，
它能排除「囤货」对估算的干扰。记满 3 个消耗周期后，可信度会变成「较准」。

**想推给家人的提醒只推给了我**
每个人各自有订阅额度，每个人都需要在自己的手机上点一次「续订提醒次数」。

**账单会超免费额度吗**
不会。一个家庭每天几十次云函数调用、几百条数据库记录，离免费额度差好几个数量级。
你可以在「云开发控制台 → 资源使用情况」自己看。
